약국 현황 지도는 어떤 공공데이터로 만들어졌나

이 문서는 약국 현황 지도 서비스가 사용하는 원천 공공데이터를 비개발자도 이해할 수 있도록 정리한 설명서입니다. 한 데이터베이스가 모든 정보를 담고 있지 않기 때문에, 인허가·요양기관번호·영업시간·인력정보를 서로 대조해 하나의 약국 목록으로 구성합니다.

최근 성공 동기화 예시: 2026-05-27 기본 약국 목록: 행안부 인허가 기준 인력정보: HIRA 요양기관 기준

한눈에 보는 구조

서비스는 먼저 행정안전부 인허가 데이터를 기준 목록으로 삼고, 여기에 HIRA 요양기관번호, 국립중앙의료원 영업시간, HIRA 약사·한약사 인력정보, 동물약국 인허가 정보를 붙입니다.

1. 인허가 기준 약국 행안부 약국 인허가 데이터로 실제 개설된 약국의 기준 목록을 만듭니다.
2. 요양기관 대조 HIRA 약국 기본목록과 매칭해 요양기관번호와 HIRA 개설일을 붙입니다.
3. 부가 정보 보강 영업시간, 동물약국 여부, 약사·한약사 등록 인력 수를 추가합니다.

기준 목록

행정안전부 약국 인허가 API

지방자치단체 인허가 자료에 기반한 전국 약국 목록입니다. 요양기관번호가 없는 약국까지 포함할 수 있어 서비스의 기본 레이어로 사용합니다.

https://apis.data.go.kr/1741000/pharmacies/info
  • 주요 정보: 관리번호, 약국명, 주소, 전화번호, 영업상태, 인허가일자, 좌표
  • 서비스 활용: 약국 존재 여부, 개설일, 폐업 제외, 지도 표시 기준
  • 한계: 요양기관번호와 약사·한약사 인력정보는 없음
동물약국

행정안전부 동물약국 인허가 API

동물용의약품 판매업 인허가 기준의 동물약국 목록입니다. 일반 약국 목록과 상호·주소를 대조해 동물약국 배지를 붙입니다.

https://apis.data.go.kr/1741000/animal_pharmacies/info
  • 주요 정보: 동물약국 인허가 관리번호, 상호, 주소, 영업상태, 인허가일자
  • 서비스 활용: 동물약국 여부 표시 및 필터
  • 한계: 일반 약국과 완전히 같은 사업장인지 이름·주소 매칭이 필요
요양기관번호

HIRA 약국 기본목록 API

건강보험심사평가원 기준의 요양기관 약국 목록입니다. 인력정보 API를 조회하기 위한 암호화 요양기관번호(ykiho)를 제공합니다.

https://apis.data.go.kr/B551182/pharmacyInfoService/getParmacyBasisList
  • 주요 정보: ykiho, 약국명, 주소, 전화번호, 개설일, WGS84 좌표
  • 서비스 활용: 행안부 약국과 대조, 요양기관번호 여부 표시, 인력정보 조인 키
  • 한계: 요양기관번호가 없는 약국은 포함되지 않을 수 있음

https://apis.data.go.kr/B551182/yadmOpCloInfoService2/getHospPharmacyOpCloList1
  • 주요 파라미터: crtrYm, yadmTp=2, opCloTp
  • 서비스 활용: 신규 개업 약국 보강, 폐업·휴업 상태 확인 보조
  • 한계: 행안부 인허가 데이터 전체를 대체하는 전수 목록은 아님
영업시간

국립중앙의료원 전국 약국 정보 API

요일별 약국 운영시간을 제공하는 핵심 소스입니다. 현재 구현에서는 약국명과 좌표를 대조해 행안부 기준 약국에 영업시간을 붙입니다.

https://apis.data.go.kr/B552657/ErmctInsttInfoInqireService/getParmacyListInfoInqire
  • 주요 정보: hpid, 약국명, 주소, 전화번호, 위도·경도, 요일별 시작·종료시간
  • 서비스 활용: 월~일, 공휴일 영업시간 표시
  • 행정 흐름: 지자체·응급의료지원센터가 취합한 정보가 새올행정시스템 등을 거쳐 표출되는 것으로 파악됨
  • 한계: 약국 현장에서 수정 접점을 모르면 실제 영업시간과 API 값 사이에 시차가 생길 수 있음
등록 인력

HIRA 의료기관별 상세정보 기타인력 API

요양기관번호(ykiho)를 기준으로 해당 약국에 등록된 약사·한약사 인력 수를 조회합니다. 신규 약국이나 오래된 조회값을 보강하는 데 사용합니다.

https://apis.data.go.kr/B551182/MadmDtlInfoService2.7/getEtcHstInfo2.7

  • 공식 데이터와 구분 표시
  • 한약사 의심 근무, 난매 의심, 창고형 약국 등 확장 가능
  • 외부 전달 시 원천 공공데이터로 분류하지 않음

서로 얽히는 지점과 애매한 매칭 영역

이 서비스의 핵심은 “한 기관의 데이터만 보여주는 것”이 아니라, 서로 다른 행정 목적의 데이터를 약국 단위로 맞춰보는 것입니다. 그래서 정확히 맞아떨어지는 영역과 사람이 해석해야 하는 회색지대가 함께 존재합니다.

행안부에는 있는데 HIRA에는 없는 약국

행안부 인허가 기준으로는 영업중이지만 HIRA 요양기관번호가 매칭되지 않는 경우입니다. 약국 개설 자체와 HIRA 공개목록·현황신고·청구 흐름은 서로 다른 행정 경로를 타므로, 이 영역은 “요양기관번호 미부여·미확인·미매칭 가능성”으로 분리해 봐야 합니다. 드물게 일반의약품 판매 중심으로 운영하려는 한약사 개설 약국이나, 성형외과 인근처럼 비급여 전문의약품 조제 중심으로 운영해 건강보험 요양급여 청구를 거의 하지 않는 약국에서는 ykiho 확인이 어려울 수 있습니다. 다만 최근에는 한약사 개설 약국도 요양기관번호를 받는 경우가 많으므로, 이를 “한약사 개설 약국은 요양기관번호가 없다”처럼 일반 규칙으로 단정해서는 안 됩니다.

HIRA에는 있는데 행안부 매칭이 흔들리는 약국

상호 표기, 주소 표기, 이전·재개설, 행정구역 변경 때문에 동일 약국인데도 문자열 매칭이 어려울 수 있습니다. 현재 구현은 이름·주소·좌표를 함께 보지만, 일부는 수동 확인 대상이 됩니다.

영업시간은 약국 목록의 원천과 다름

행안부/HIRA 기본목록에는 영업시간이 없습니다. 영업시간은 국립중앙의료원 응급의료포털 약국정보 API에서 가져와 별도 매칭합니다. 따라서 약국은 존재하지만 영업시간이 비어 있거나 오래된 값으로 남는 경우가 생길 수 있습니다.

인력정보는 ykiho가 있어야 조회 가능

HIRA 기타인력 API는 ykiho를 입력해야만 조회됩니다. 행안부 인허가 약국 중 ykiho가 없는 약국은 공식 HIRA 인력조회가 불가능하므로, 현장 제보와 공식 등록 인력은 반드시 구분해 표시해야 합니다.

요약: 행안부는 “약국 인허가 전수성”, HIRA는 “요양기관번호와 등록 인력”, NMC는 “운영시간”에 강합니다. 세 데이터는 같은 약국을 바라보지만 행정 목적이 달라, 일부 약국은 한쪽에는 있고 다른 쪽에는 없을 수 있습니다.

영업시간 데이터가 만들어지는 행정 흐름

국립중앙의료원 응급의료포털 약국정보 API는 단순히 약국이 직접 입력한 영업시간을 그대로 보여주는 구조라기보다, 현장·지자체·응급의료 행정망을 거쳐 공개 API로 배포되는 정보로 이해하는 편이 자연스럽습니다.

약국 현장 영업시간 변경, 공휴일 운영 여부, 당번 운영 정보가 실제로 발생합니다.
보건소·응급의료지원센터 지자체 또는 지역 응급의료지원센터가 영업시간·공휴일 운영 정보를 취합합니다.
새올행정시스템 취합된 정보가 지자체 행정 시스템에 반영되는 것으로 파악됩니다.
NMC 공개 API 응급의료포털 약국정보 API를 통해 요일별·공휴일 영업시간이 배포됩니다.
일상 영업시간의 약한 연결고리

통상적으로 약국은 개설 시점에 영업시간을 한 번 전달하고, 이후 평상시 영업시간이 바뀌어도 어디에 연락해야 공개 API까지 반영되는지 모르는 경우가 많습니다. 이 때문에 실제 현장 영업시간은 바뀌었는데 NMC API에는 개설 당시 또는 과거에 전달된 시간이 계속 남아 있을 수 있습니다.

공휴일·당번 정보의 별도 흐름

공휴일에 어떤 약국이 여는지는 보건소 또는 관련 기관이 별도로 취합하고, 이를 행정 시스템에 반영한 뒤 API에 표출하는 흐름으로 보입니다. 즉 평상시 영업시간과 공휴일 운영정보는 관리 맥락이 다를 수 있습니다.

문서상 표현: 이 행정 흐름은 현재 확인된 운영 정황을 설명한 것입니다. 기관에 공유할 때는 “영업시간은 개설 시점에 전달된 값이 오래 유지되는 경우가 있고, 변경 시 보건소·응급의료지원센터·새올행정시스템 등을 거쳐 NMC API에 반영되는 것으로 파악된다”처럼 확인 가능한 표현을 쓰는 것이 안전합니다.

요양기관번호가 없는 약국은 무엇인가

요양기관번호는 HIRA 인력 API를 조회하기 위한 핵심 키입니다. 다만 지도에서 “요양기관번호 없음”으로 보인다고 해서 곧바로 무허가 약국이거나, 실제로 건강보험 제도 밖의 약국이라고 결론내릴 수는 없습니다.

확인된 제도적 기준

국민건강보험법상 약사법에 따라 등록된 약국은 요양급여를 실시하는 요양기관 범주에 들어갑니다. 또한 요양기관 현황신고 서식에는 약국의 요양기관 기호, 약사·한약사 인원 현황, 청구 소프트웨어, 요양급여비용 수령 계좌 등이 함께 다뤄집니다.

공개 API에서 안 보이는 이유

행안부에는 영업중 약국으로 존재하지만 HIRA 공개목록에서 ykiho가 매칭되지 않는 경우는 신규 개설 후 반영 지연, 상호·주소·좌표 매칭 실패, 이전·재개설, 공개 데이터 제공 범위 차이 등이 원인일 수 있습니다. 절차상으로는 약국 개설을 보건소에 신청한 뒤, 요양기관번호를 받기 위해 HIRA 쪽에 별도 서류를 제출하는 흐름이 뒤따릅니다.

드문 운영 모델

ykiho가 없는 약국은 실제로는 드문 편입니다. 가능한 경우로는 일반의약품 판매만 상정한 한약사 개설 약국, 또는 비급여 전문의약품 조제만 상정해 요양급여비용 청구를 하지 않는 약국이 있습니다. 하지만 요즘은 한약사 개설 약국도 요양기관번호를 받는 편으로 이해하는 것이 더 현실에 가깝습니다.

면허 등록과 청구 가능성

한약사 개설 약국이 요양기관번호를 받았더라도, 등록 인력이 한약사만인 경우 이른바 전문의약품 조제에 대한 건강보험 청구는 제한될 수 있습니다. 반대로 해당 요양기관에 약사 면허자가 근무 인력으로 등록되어 있으면, 그 등록 상태를 전제로 전문의약품 조제 청구가 가능해지는 것으로 이해됩니다. 따라서 요양기관번호의 존재와 약사·한약사 등록 인력 구성은 함께 보아야 합니다.

서비스에서의 안전한 표기

따라서 서비스에서는 “요양기관번호 X”를 “HIRA ykiho 미확인” 또는 “HIRA 인력조회 불가”에 가깝게 해석합니다. 공식 인허가 여부는 행안부 영업상태로, 등록 인력 여부는 HIRA ykiho가 확인되는 약국에 한해 별도로 봐야 합니다.

비개발자를 위한 핵심 해석

왜 행안부가 기준인가

약국 개설 자체는 지방자치단체 인허가로 관리됩니다. 따라서 요양기관번호가 없는 약국까지 포함하려면 행안부 인허가 자료가 기준이어야 합니다.

왜 HIRA가 필요한가

약사·한약사 등록 인력정보는 HIRA 요양기관번호로 조회됩니다. 행안부 자료에는 ykiho가 없으므로 HIRA 기본목록과 대조해야 합니다.

왜 영업시간은 별도인가

행안부와 HIRA 기본목록에는 영업시간이 없습니다. 그래서 국립중앙의료원 약국정보 API의 요일별 운영시간을 별도로 붙입니다.

표현상 주의: HIRA 기타인력 API는 개인별 면허 원부가 아니라 요양기관에 등록된 인력 현황입니다. 외부 설명에서는 “약사/한약사 면허 등록 여부”보다 “요양기관별 약사·한약사 등록 인력 수”라고 표현하는 것이 더 정확합니다.

현재 서비스에서의 한계와 보완 방식

이슈 발생 이유 현재 보완 방식
요양기관번호가 없는 약국 신규 반영 지연, HIRA 서류 제출·반영 전 상태, 비청구 운영 모델, 공개 데이터 범위, 이름·주소 매칭 실패 등이 겹칠 수 있음 행안부 인허가 목록을 기준으로 삼고, HIRA 미매칭을 “ykiho 미확인”으로 분리해 후속 점검
신규 개업 약국의 인력정보 누락 분기 파일은 최신 개업분을 즉시 반영하지 못함 HIRA 기타인력 API를 ykiho별로 조회해 신규 약국 인력정보 보강

현장 정보와 공식 등록 정보의 차이 실제 근무와 HIRA 등록 현황 사이에 시차 또는 누락 가능성 존재 공식 데이터와 별도로 현장 제보/관리자 승인 배지를 분리 운영

별도 쟁점: 포털 노출과 데이터 정합성

아래 내용은 원천 공공데이터 자체의 설명이라기보다, 약국 정보가 네이버 지도 등 민간 포털에 표시되는 과정에서 생길 수 있는 운영·정책상 쟁점을 정리한 것입니다.

1. 약사·한약사 등록 인력 정보를 포털이 표시하지 않는 문제

네이버 지도 등 대형 포털은 현재 약국별 약사·한약사 등록 인력 상태를 일반 이용자 화면에 표시하지 않습니다. 과거 또는 현재의 답변 맥락에서는 기술적으로 어렵다거나, 데이터의 실시간성이 낮아 표시하기 어렵다는 취지의 설명이 있었던 것으로 이해됩니다.

다만 데이터 자체가 전혀 없는 것은 아닙니다. HIRA 기타인력 API를 통해 요양기관번호가 있는 약국의 등록 인력 수를 조회할 수 있습니다. 따라서 쟁점은 “데이터가 존재하느냐”보다 “어느 기준일의 데이터를, 어떤 책임 범위와 설명 문구로, 포털 화면에 표시할 수 있느냐”에 가깝습니다.

표현상 주의: 네이버가 특정 직역 갈등에 얽히지 않기 위해 소극적으로 답변했을 가능성은 하나의 해석일 수 있지만, 확인된 사실처럼 단정하기보다는 “직역 간 분쟁 가능성, 최신성 책임, 오류 민원 부담 등이 표시를 주저하게 만드는 요인일 수 있다” 정도로 쓰는 편이 안전합니다.

2. 영업시간 최신화는 포털 개별 입력보다 공적 엔드포인트 중심이 바람직

대한약사회가 네이버 스마트플레이스 등록이나 약국 정보 최신화 캠페인을 진행하는 것은 단기적으로 포털 검색 품질을 높일 수 있습니다. 그러나 장기적으로는 각 포털에 개별 입력을 유도하는 방식이 데이터 파편화를 만들 수 있습니다.

이상적인 구조는 약국이 약국전산프로그램 또는 별도 표준 입력 장치를 통해 영업시간·휴무·전문서비스 정보를 한 번 입력하고, 이 정보가 보건소·응급의료지원센터·새올행정시스템 등 정부 행정망으로 전달된 뒤, NMC 등 정부 관리 엔드포인트를 통해 네이버·카카오·공공앱이 동일한 값을 가져가는 방식입니다.

약국 입력 약국전산프로그램 또는 표준 입력 화면에서 영업시간·휴무 정보를 등록합니다.
공적 검증·취합 분회, 보건소, 응급의료지원센터가 필요한 범위에서 확인·보정합니다.
정부 관리 DB/API 새올행정시스템 또는 관련 공공 API에 단일 기준값으로 반영합니다.
포털·서비스 활용 네이버, 카카오, 공공 지도, 약사회 서비스가 같은 원천을 조회합니다.
포털 직접 입력 방식의 장점

네이버 스마트플레이스처럼 이미 약국과 이용자가 많이 접하는 채널을 활용하므로, 단기 홍보와 노출 개선에는 빠르게 효과가 날 수 있습니다.

포털 직접 입력 방식의 위험

네이버에는 최신인데 공공 API에는 낡은 값이 남거나, 반대로 공공 API에는 수정됐지만 포털에는 반영되지 않는 데이터 역류·파편화가 생길 수 있습니다.

3. 대한약사회 패널약국 설문의 의미

제시된 2026년 5월 패널약국 설문은 약국이 현재 정보를 어디에 등록하고, 얼마나 자주 수정하며, 포털의 “현재 영업중” 표시 정확도를 얼마나 중요하게 보는지 확인하려는 구조입니다.

설문 문항군 확인하려는 문제 데이터 정책상 의미
네이버 스마트플레이스 등록 여부 약국이 포털 자체 관리 체계에 들어와 있는지 포털 직접 등록 방식의 도달률 측정
영업시간 안내 방식 출입문, 복약봉투, 네이버, 약사회, SNS 등 정보 채널 분산 정도 정보 파편화의 현재 수준 파악
정보 점검·수정 빈도 정보 최신화가 정기적으로 이뤄지는지 월 1회 점검 캠페인의 필요성 평가
포털 영업시간과 실제 운영시간 일치도 이용자 화면의 신뢰도 공공 API 또는 포털 데이터 정합성 개선 근거
전문서비스 표시 필요성 동물의약품, 공공심야, 다제약물관리 등 부가정보 수요 단순 영업시간을 넘어 약국 기능 정보 표준화 필요
네이버 등록 교육·캠페인 참여 의향 현장 약국이 포털 관리 교육을 받아들일지 단기 실행안으로는 유용하지만, 장기적으로는 공적 원천 연계가 필요
정리: 이 설문은 포털 정보 최신화의 현황을 파악하는 데 유용합니다. 다만 정책 제안의 방향은 “네이버에만 잘 등록하자”보다 “약국이 한 번 입력하면 공공 엔드포인트와 포털이 같은 값을 쓰게 하자”로 잡는 것이 데이터 정합성 측면에서 더 안정적입니다.
단기 과제

네이버 스마트플레이스 등록·수정 교육으로 현재 포털 검색의 오류를 줄입니다.

중기 과제

대한약사회 또는 분회 차원에서 약국 영업시간·휴무·전문서비스 정보를 표준 항목으로 수집합니다.

장기 과제

수집된 정보가 정부 관리 엔드포인트로 흘러가고, 네이버 등 포털은 그 공적 API를 참조하도록 협의합니다.

이 문서는 공개 API 키를 포함하지 않습니다. 실제 운영에서는 data.go.kr 발급 서비스키와 Supabase 서비스 권한을 서버 측 자동화에서만 사용합니다.
