공공 API로 약사·한약사 등록 인력 표출하기

결론부터 말하면, “요양기관번호가 있는 약국”에 대해서는 공공 API로 약사·한약사 등록 인력 수를 표출하는 것이 기술적으로 어렵지 않습니다. 핵심은 약국 목록 API와 HIRA 기타인력 API를 같은 약국 단위로 연결하는 일입니다.

요약

개발자 입장에서 이 기능은 새로운 행정 시스템을 만드는 일이 아니라, 이미 공개된 API를 조합해 사용자 화면에 읽기 쉽게 보여주는 작업에 가깝습니다.

1개 키 HIRA 암호화 요양기관번호 ykiho가 있으면 기타인력 API를 조회할 수 있습니다.
2개 코드 071=약사, 072=한약사를 집계하면 약국별 등록 인력 수가 됩니다.
하루 캐시 매번 실시간 호출할 필요 없이 하루 1회 또는 변경 감지 시 갱신하면 충분합니다.

필요한 공공 API

역할 API 가져오는 것
약국 기준 목록 행정안전부 약국 인허가 API 약국명, 주소, 인허가일자, 영업상태, 좌표
요양기관번호 확보 HIRA 약국 기본목록 API 암호화 요양기관번호 ykiho, HIRA 개설일, 주소, 좌표
등록 인력 조회 HIRA 의료기관별 상세정보 기타인력 API 요양기관별 약사·한약사 등 기타인력 구분과 수

구현 흐름

1. 약국 목록 수집 행안부 인허가 자료로 현재 영업중 약국의 기준 목록을 만듭니다.
2. HIRA 목록 대조 이름, 주소, 좌표를 이용해 HIRA 약국 기본목록의 ykiho를 붙입니다.
3. 기타인력 조회 ykiho별로 HIRA 기타인력 API를 호출하고 071, 072를 집계합니다.
4. 화면 표출 약사 2명, 한약사 1명처럼 기준일과 함께 표시합니다.

프로그래머 입장에서의 난이도

쉬운 부분

API 호출 자체는 단순합니다. serviceKey, pageNo, numOfRows, ykiho를 넣고 응답을 받아 직종 코드별로 숫자를 합산하면 됩니다. 프론트엔드에는 “약사 N명 / 한약사 N명 / 조회 기준일”만 내려주면 됩니다.

주의할 부분

어려운 지점은 호출이 아니라 “같은 약국인지 맞추는 일”입니다. 행안부 인허가 자료에는 ykiho가 없기 때문에 HIRA 약국 목록과 이름·주소·좌표를 대조해야 합니다. 새로 개업한 약국은 반영 시차도 고려해야 합니다.

예시 코드

실제 서비스에서는 API 키를 브라우저에 노출하지 않고 서버나 배치 작업에서 호출합니다. 아래는 구조를 설명하기 위한 간단한 의사 코드입니다. 

// 1. ykiho가 있는 약국만 대상으로 HIRA 기타인력 API 호출
const url = new URL("https://apis.data.go.kr/B551182/MadmDtlInfoService2.7/getEtcHstInfo2.7");
url.searchParams.set("serviceKey", process.env.DATA_GO_KR_SERVICE_KEY);
url.searchParams.set("pageNo", "1");
url.searchParams.set("numOfRows", "100");
url.searchParams.set("ykiho", pharmacy.ykiho);

const rows = await fetchXmlOrJson(url);

// 2. 직종 코드별 집계
const pharmacistCount = sum(rows.filter(row => row.typeCode === "071"));
const herbalistCount = sum(rows.filter(row => row.typeCode === "072"));

// 3. DB에 저장하고 화면에는 기준일과 함께 표시
await saveStaffSnapshot({
  pharmacyId: pharmacy.id,
  ykiho: pharmacy.ykiho,
  pharmacistCount,
  herbalistCount,
  checkedAt: new Date().toISOString(),
  source: "HIRA 기타인력 API"
});

화면에는 이렇게 표시하면 됩니다

표시 항목 예시 이유
등록 인력 수 약사 2 한약사 1 사용자가 직관적으로 이해할 수 있는 최종값입니다.
조회 기준 2026. 05. 28. HIRA 기타인력 API 기준 실시간 원장이 아니라 특정 시점의 공공 API 조회값임을 명확히 합니다.
요양기관번호 없음 HIRA ykiho 미확인 인허가 약국이지만 HIRA 인력 API 조회 키가 없다는 뜻입니다. 비청구 운영, 신규 반영 지연, 매칭 실패 등이 가능하므로 무허가나 폐업으로 오해하지 않게 합니다.
공식/제보 구분 공식 등록 인력 / 현장 제보 HIRA 등록값과 커뮤니티 제보는 법적 성격과 신뢰도가 다릅니다.

왜 민간 포털도 구현할 수 있나

네이버 지도 같은 민간 포털이 이미 약국 위치, 전화번호, 영업시간, 리뷰, 길찾기를 제공한다면, 기술적으로는 약국 상세 화면에 “공공 API 기준 등록 인력” 영역을 하나 추가하는 것과 크게 다르지 않습니다. 필요한 것은 화면 디자인보다 데이터 정책입니다.

IT적으로 단순한 이유

포털은 이미 약국 식별자와 위치 DB를 가지고 있습니다. 여기에 HIRA ykiho 매칭 테이블을 붙이고, 하루 한 번 기타인력 API를 돌려 캐시하면 됩니다. 사용자 요청 때마다 공공 API를 직접 때릴 필요도 없습니다.

정책적으로 어려운 이유

문제는 “표시할 수 있느냐”보다 “오류·최신성·직역 갈등·민원 책임을 어떻게 설명하느냐”입니다. 따라서 화면에는 반드시 출처와 기준일, 그리고 “요양기관별 등록 인력 현황”이라는 표현을 함께 붙이는 편이 안전합니다.

한 줄 결론

공공 API만으로도 요양기관번호가 확인되는 약국의 약사·한약사 등록 인력 수를 표출하는 것은 충분히 구현 가능합니다. 다만 “개인 면허 원부”나 “현재 매장에 실제 근무 중인 사람”을 보여주는 것이 아니라, HIRA 요양기관 기준으로 등록된 인력 현황을 기준일과 함께 보여주는 기능이라고 설명해야 정확합니다.

이 문서는 공개 공유용으로 작성되었으며 API 서비스키를 포함하지 않습니다.
